# 项目理念：为「看」而造，不为「赢」而造

VERA20K-SuperAI **不是竞技 AI**：它不追求胜率最高，不追求微操极致，也不追求冷冰冰的最优解 ——
把每一局都算成一道标准答案，然后照着答案机械执行。

它面向的是**「电子斗蛐蛐」与观战场景**：把 8 / 30 / 120 家电脑放进同一张地图，让它们带满编部队
互相撞在一起，把一场遭遇战变成一整个下午值得看的混战。

所以我们更在意的不是"谁打得更聪明"，而是多方势力交火时的**进攻欲望、兵种碰撞与战场观赏性**。
每局要打得**热闹、胶着、充满戏剧张力**：拉锯、翻盘、满屏单位互撞、基地被打穿又重新铺起来。

## 一局"好"的判据

- **前 5 分钟有没有打起来** —— 开局不能是各建各的家。
- **10 分钟有没有拉锯** —— 一边倒不算好局。
- **有没有哪一家挨打之后翻回来** —— 翻盘是最好看的部分。
- **满屏是不是一直有仗在打** —— 中间空个两三分钟，观感就断了。

## 我们刻意接受的非最优

| 我们选择 | 而不是 | 已知代价（接受） | 落到的机制 |
| --- | --- | --- | --- |
| 铺满地图、持续进攻 | 攒一波再决胜 | 帧率压力、单位堆积 | Mass Skirmish 的扩厂触发器 + 全员冲锋 |
| 超武充满就放、基地被打掉就重建 | 精打细算憋大招 | 资源浪费、AI 偶尔犯傻 | `AIBuildCounts` 计划目标、维修厂 `AIBuildThis=yes` |
| 全员冲锋 FFA 乱战 | 结盟、龟缩、最优兵种配比 | 平衡不完美、有人被围殴 | 观战图默认 FFA、All to Hunt |
| 观战位无敌 + 全图常亮 + 错峰 Hunt | 战争迷雾、真人微操 | 没有竞技公平性 | 地图触发器（每户 `300 + slot%30*2` 秒） |
| 数据改动可复现、可审计 | 手改 INI 图快 | 构建脚本比改数值复杂 | `build_mass_skirmish.py` + `build-report.txt` 的 SHA256 |

## 非目标

- **不做天梯与竞技平衡**：没有胜率榜，也没有"这个阵营偏强"的补丁。
- **不追求"能打赢玩家"**：AI 的对手是别的 AI，玩家是观众。
- **不为最优解牺牲画面**：能选更聪明的打法时，先选更好看的那一个。
- **不新增单位类型**：引擎的类型注册表沿用原版数量，只改既有数据。

## 这对文档意味着什么

README 把观战放在第一屏：先说清"这不是竞技 AI"，再说装哪个模组、怎么开一局、能看到什么。
判断标准也写在文档里 —— 一局值不值得看，不取决于谁赢。

所以「已知限制」里 Stage 2 未联调必须如实写：帧率与观感还没实机联调，就不能用"流畅"这类
没有测过的词。**诚实的边界声明也是理念的一部分** —— 吹得比实测好，等于骗自己。
